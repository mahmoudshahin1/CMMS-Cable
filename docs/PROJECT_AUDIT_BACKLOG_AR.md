# سجل مراجعة المشروع وخطة المعالجة

هذا الملف يجمع الملاحظات التي ظهرت عند مراجعة فرع `feature/mobile-logic` في 6 نوفمبر 2026. الغرض متابعة الإصلاحات بالتتابع قبل اقتراح توسعات جديدة. ترتيب البنود يراعي أثرها على صحة البيانات والأمان أولًا.

## قواعد التعامل

- [ ] راجع الكود وملفات SQL الحالية قبل اعتماد وصف قديم في README أو ملاحظات التسليم.
- [ ] لا تطبق migrations على الإنتاج: سجل الإنتاج مختلف عن migrations المحلية وبعض التغييرات طُبقت يدويًا. المستخدم رفض إنشاء فرع Supabase؛ لا يُنشأ فرع ولا تُنفذ كتابة على الإنتاج. يلزم إعداد بيئة محلية أو توفير بيئة تطوير لاحقًا لاختبار SQL.
- [ ] لا تغيّر تعديل المستخدم الموجود في `PROJECT_CONTEXT_CODEX.md` عرضًا.
- [ ] بعد إصلاح كل بند، حدّث حالته وسجل الملفات المتأثرة والتحقق الذي نُفذ.

## الأولوية 1 — توحيد عقد اختبار التشغيل بين Flutter وSupabase

**الحالة: عقد Flutter المحلي اختُبر؛ الميزة موجودة بالفعل على Supabase الإنتاج، لكن سلسلة migrations المحلية متأخرة. ظهر خلل صلاحيات RPC على الإنتاج ويجب إصلاحه قبل اعتمادها.**

- [x] تحديد عقد واحد لنتائج الاختبار `fixed`, `needs_followup`, `not_fixed` وحالات أمر العمل المقابلة.
- [x] توثيق عقد Flutter واختبار تطابق أسماء معاملات RPC محليًا.
- [x] تأكيد وجود outcome-aware RPC وفحص الدور والقسم وسلوك الارتداد في الإنتاج بقراءة schema فقط.
- [ ] مصالحة migrations المحلية مع سجل الإنتاج (11 محلية مقابل 22 حية، بلا مصدر SQL لبعض تغييرات الإنتاج). تفاصيل المقارنة والخطة في `docs/SUPABASE_MIGRATION_DRIFT_AR.md`.
- [ ] إصلاح صلاحيات RPC: الدالة `SECURITY DEFINER` وقابلة للتنفيذ بواسطة `anon`/`PUBLIC`، وقراءة نتيجة الأمر idempotently تحصل قبل التحقق من هوية المستدعي. راجع وأصلح ترتيب التحقق والصلاحيات في بيئة اختبار قبل أي نشر.
- [ ] اختبار SQL والصلاحيات بأدوار وأقسام منفصلة. لم يُنشأ فرع Supabase بناءً على رفض المستخدم؛ لا توجد حاليًا بيئة SQL تطويرية مؤكدة.
- [x] تشغيل اختبار Flutter المحدد (13 اختبارًا) و`flutter analyze`؛ كلاهما نجح محليًا. هذا لا يثبت صحة SQL على قاعدة حية.

**الأدلة الحالية:** Flutter يرسل النتيجة والمدة؛ تمت إضافة اختبار محلي لمطابقة معاملات RPC، ونجح الاختبار المستهدف (13 اختبارًا) و`flutter analyze`. فحص MCP للـschema فقط وجد 22 migration في المشروع الحي مقابل سلسلة محلية أقدم، ووجد أن `rpc_confirm_test_run` الحية تتعامل مع النتائج والأقسام والارتداد وأن `work_orders.checks` موجود. كما وجد أن الدالة `SECURITY DEFINER` ومنفذة لـ`anon`/`PUBLIC`، وأن قراءة سجل الأمر idempotency تسبق التحقق من الهوية. لم تُقرأ صفوف تشغيلية ولم تُستدعَ RPC ولم تُنفذ أي كتابة. رفض المستخدم إنشاء فرع Supabase؛ لا يوجد تحقق runtime لـSQL.
