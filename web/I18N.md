# Web UI language rules

- **English is the default language.** Arabic is the translation, switched with the EN / عربي button in the header.
  The choice is saved in `localStorage` (`cmms-locale`), so people who already picked Arabic keep it.
- **Every visible string lives in `src/stores/locale.ts`, under both `ar` and `en`.** Use `t('section.key')`.
  No hardcoded Arabic or English in templates or scripts (including error messages and `aria-label`s).
- Helpers in `src/lib/*` take a `locale` argument (default `'en'`). Pass `locale.locale` from the view.
  Never hardcode `'ar-EG'` in `Intl` / `toLocaleString`; choose it from the current locale.
- Layout must work in both directions: use logical classes (`text-start`, `ms-*`, `ps-*`, `start-*`, `ltr:` / `rtl:`),
  and pick arrows by `locale.direction`.
- Text that people type into the app (event summaries, reasons, comments) is shown as entered, not translated.
- Run `npm run check:i18n` before pushing. It fails if a key exists in only one language
  or if an English value contains Arabic letters.
